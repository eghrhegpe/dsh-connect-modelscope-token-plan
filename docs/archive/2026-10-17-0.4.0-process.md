## 出图工具改两段式（5b3b588）

**病灶**：旧形状是「一次调用 `await` 到终态」，`drawTimeoutMs`（15 分钟）于是同时是「这张图值
不值得等」和「一轮对话被占住多久」的上限——把上游排队的代价直接转嫁成 agent 的停顿（提交里
的实测排队 61s–537s，免费池波动）。

**判据：一次调用只做两件事之一**

1. 不带 `jobId` → 提交，然后只在 `drawWaitMs`（新增配置，默认 90s）内等；等到返回 `done`，
   没等到返回 `status: pending` + `jobId`；
2. 带 `jobId` → 只查那个任务，同样最多等 `drawWaitMs`。

`drawTimeoutMs` 因此回到它本来的语义：**从提交算起的总放弃线**（跨调用累计）。

**取舍：刻意不新增第二个工具**——peer 的 tools registry 没有 unregister，多注册一个工具等于在
Host 里永久占位；同一工具用可选参数分两段，注册面不变。

**两个刻意的判定**

- `pending` **不是失败**：不抛错、不进冷却门。进冷却会把续查这条路堵死，而那正是分段查询的
  目的。只有真失败（提交失败 / 上游 FAILED / 越过总放弃线）才 `cooldown.fail()`。
- 作业表**只在本进程内有效**：不在表里（插件重启过）时给可操作说明，并明说「原任务可能仍在
  生成，但结果不保证还能取回」——上游终态记录会被回收（SPIKE §坑 5），不承诺换个方式还能取回。

**实现**：`runDrawOnce` 拆成 `submitDrawTask` + `awaitDrawTask` 两个原语，它自己变成两者的组合
——等待循环只有一份，分段与一次性共用；它的 15 处既有断言行为一字未改（含超时抛错与「可能
仍在生成」文案）。新建 `draw-jobs.ts` 存 `jobId`（= 上游 `task_id`，少一层映射）、提交时刻与
累计轮询数，容量上限淘汰最旧。

**回归钉子**：新增 `draw-jobs.test.mjs`（9 组，钉容量淘汰/副本语义/累计）；
`draw-runtime.test.mjs` 补两段式 12 组（pending 不阻塞、续查不重复提交、pending 不进冷却、
真失败才冷却、越过总放弃线、工具硬护栏按 waitMs 设、jobId 进出参契约）；mutate-spec 加 7 条
（pending 变 failed / 总放弃线消失 / 续查不查表 / 护栏回到总放弃线 / 容量不淘汰 / get 返引用 /
notePolls 改赋值），21 条全 KILLED。

## 出图设置的三件套（8960ec6）

**病灶**：`draw.json` 是 provider-store 同款缺陷的**漏网第四条**，四件全缺——

- 无写串行化：并发 `saveEnabled` + `saveModelId` 实测**丢一次保存**；
- 无 ADR-006 写守卫：`version=2` 的文件被**降级覆写**；
- 读侧无 `versionNote`：版本不认识时**静默读作「未设置」**；
- `doctor` 从 v0.2 起就看不见这个文件。

**修法/判据**：`writeChain`／版本守卫／`versionNote` 上收为 `state-store` 公共原语，
`provider`／`usage` 改用后行为不变；`save*` 统一 `throw` 方言。

**顺修**：`draw.ts` 脱敏副本漂移（缺 `sk-`／键值对两组正则）、`ms-auth` 的 `state()` 解构即崩、
`summarizeCatalog` 冗余 `find`。脱敏那条是本节最重的一条：上游把请求体原样回显时，凭据可能
一路进面板与日志。

**回归钉子**：新增 `draw-store.test.mjs`（并发/守卫/versionNote）并过变异验红。

## 单源化：允许清单与错误码（ae91db7）

**病灶**：同一份允许清单有**六处**各自解释（`resolveAllowedList` / `filterByEnabled` /
`isModelEnabled` / 快照 `enabledCount` / 路由 `enabledCount` / 客户端 `saveRoster` 归一），
而且解释得不一致——`filterByEnabled` 把 `[哨兵,"a/A"]` 读成「提供 a/A」，`resolveAllowedList`
同时说那是 none，同一个清单有两个答案。

**修法**：`__hide_all__` 哨兵搬进 `shared/wire.ts`（线编码的一部分）；新建
`shared/allow-list.ts` 把三态收敛成判别联合，全插件只有 `parseAllowedList` 一处解释，其余都是
联合上的模式匹配。错误码表迁到 `shared/codes.ts`，删掉 `client/snapshot.ts` 的 `CLIENT_CODE`
副本（它的存在理由——浏览器无法 import Host 模块——随 `shared/wire.ts` 被双端运行时导入
早已过期），`GUIDANCE_BY_CODE` 的键集顺带升级为编译期全函数覆盖。

**回归钉子**：`allow-list.test.mjs`（7 节，含 `[哨兵,id]` 混排钉）。

## publisher 结构承重（ae91db7）

**病灶**：130 行临界区靠注释论证「位置严密」——没有任何东西保证下一个人不去中间插一个 `await`。

**修法**：拆 `gatherPublish`（async，四个 `await` 全住这里）+ `commitPublish`（**非 async
函数**），用语言级的「无挂起点」保证替掉注释论证；相位从散文升级为 `publisherPhaseOf` 五相位
推导（idle/serving/failing/broken/disposed），不双写契约字段——双写的方向静默漂移从根上不可能。

**回归钉子**：`provider-publish` 加相位钉；`provider.test` 钉住「index 不得直接 publish」，
双驱动复活即红。

## 双驱动收编为 reconciler（ae91db7）

**病灶**：轮询定时器与四条写路由是两套互不知情的发布逻辑；`runPoll` 那个「fetch 期间被改就跳过
本轮」的 contextWindow 补丁，是没有 desired-state 控制器的典型症状——丢一次更新、再等一个周期。

**修法**：新建 `provider-reconcile.ts`：读 desired → 拉目录 → 复查 desired → publish，串行链 +
dirty 合并；轮询定时器与四条写路由全部降级为「标记 dirty」，谁都不用记得别人是不是也在 publish。

**两个刻意的行为改变**：

- fetch 失败**不再**降级成发布空目录——一次瞬时抖动会把已服务的模型全部撤下，那是破坏不是重试；
- fetch 期间 desired 被改 → 原地重跑，保存路由 `await` 返回时新值一定已落地。

**回归钉子**：`reconcile.test.mjs`（7 节，含「fetch 期间被改 → 两遍 fetch 一遍 publish」）；
`provider-routes` 加端到端注册/摘除钉（reconcile 变 no-op 就红）。

## provider 块读不到时省略（53c9902）

**病灶**：调研「上帝快照拆端点」时发现**端点其实早已拆好**（`/provider`、`/draw` 独立存在，
客户端也写了「快照优先 + 路由兜底」）——真正坏掉的是兜底那条路径**从来没跑起来**：旧实现在
provider 块聚合失败时塞一个填满默认值的块（`enabled:false`、`allowed:"all"`、`roster:[]`），
那个形状**看起来就是一个答案**，客户端据此判定「块在」（`hasProviderBlock`），于是不再
`GET /provider`，只能拿编出来的值渲染。同一件事 draw 块走的是另一套（失败即省略），provider
那条更差。

**修法**：统一为**省略**——`wire.ts` 的 `provider?` 变可选（与 `draw?` 同纪律），Host 失败即省略，
客户端的兜底路径随之真正生效（兜底也失败才用 `DEGRADED_PROVIDER`）。降级形状因此只剩客户端
一份，而不是 Host 编一份、客户端再编一份、wire 注释里还写着第三份。省掉的块不许把原因一起
带走：块级失败进 `shapeWarnings`（格式 `label source failed (code): error`），否则操作者只看到
「未接入」，而真相是「Host 读不到自己的状态」。

**未做（估价后不建议）**：真把 `/snapshot` 拆成多个按域端点——几乎所有块都依赖或本身就是网络
数据（provider 的 roster 来自目录），`soft()` 已实现失败隔离，拆开只增加契约面与客户端编排复杂度，
不带来新的隔离能力。

**回归钉子**：`routes.test.mjs` 新增一节钉「省略 + 原因留档」；mutate-spec 加 2 条（塞回降级块 /
删掉警告）。

## 自我描述与同族体检（bbf29db / 31dee4f）

**病灶**：「受控复制」「零覆盖」这类对自身状态的宣称此前**没有任何门禁**，是注释里唯一没人管
的部分。实测发现多处与事实不符，其中两处已经误导过维护——拿 sensenova 的经验去改 modelscope
的「同一个文件」，而两份只有名字一样。

**实测结果**（措辞统一改成「定性判断 + 实测量级 + 复核命令」，数字可随时重算）：

- `provider-publish.ts`「差异只有三个标签」→ 代码重叠 77%，差异不止标签（vision 判定来源、
  usage 接线位置也不同）；
- `draw-runtime.ts`「改错本文件不会让任何门禁变红」→ 陈述已过时，补上被钉住的 7 个符号，
  未覆盖的只剩 `defineDrawTool` 落 registry 那一段；
- `draw-register.ts` 删掉「与 `llm-adapter.ts` 一样不能被离线测试导入」（已被 peer-stub-loader 推翻）；
- `use-snapshot-polling.ts`「受控复制」→ 实测重叠 12%；`http.ts` → 42%；`format.ts` →
  73%（sensenova）/ 45%（agnes 已分家）。

**门禁**：`tools/dev` 的同族同源度体检，判据是**顺序无关的去注释代码行重叠**——diff 行数被注释
语言骗（`provider-publish.ts` 报出 464 行差异，看着像两份不同实现，真实重叠 77%），LCS 被函数
顺序骗（`util.ts` 两侧函数集合几乎相同只是排列不同，LCS 给 32%，真实重叠 94%）。`--claims` 逐
文件核对头注里的同源宣称，`--strict` 让不符变成非零退出。四条边界按实证钉死：同形/同款不算宣称、
裸「同源」不算（`const.ts` 那句是 web 的 same-origin）、点名≠宣称、指名只在被点名的仓库上核对。
**宣称判行、指名判段**——这个不对称是被变异检验逼出来的：整段判定时，一句「不能照抄」会把夹在
同一段里的假宣称一起吞掉（第一版漏抓）。
