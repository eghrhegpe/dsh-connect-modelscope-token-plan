# 0.6.0 过程档案——额度耗尽集合接线（2026-10-18）

> 这不是入门路径。公开行为变化看 [CHANGELOG.md](../../CHANGELOG.md) 的
> `[0.6.0]` 节；契约规则看 [PROVIDER-M4.md](../PROVIDER-M4.md) §15。
> 本文只记病灶、判据与取舍。

## 一、病灶：参数在、生产者不在

`buildDescriptors`（picker 丢弃）与 `rosterWithAvailability`（面板灰显 + 禁勾选）
从 M4 甚至 0.2.0 起就带着 `unavailableModelIds` / `unavailableIds` 参数，
`catalogSignature` / `quotaSignatureOf` / `quotaSignature` 三道签名机制也为
「耗尽集合变化要触发重建」建好了——但**没有任何调用方填过非空数组**：
`snapshot-aggregate.ts` 与 `routes/provider.ts` 两处 roster 都硬编码 `[]`，
reconciler 调 `publish(entries, enabledIds, [])`，M4 注释原话「本插件暂无额度
耗尽聚合」。后果：早上耗尽过的模型继续躺在选择器里，用户选它 = 一次注定 429。
这是功能性评审（2026-10-17）锐评出的四项「实测属实/设计取舍」里唯一带
**用户可见后果**的未接线条目，也是本轮补它的理由。

## 二、判据：为什么是「quota 事件 + 时间窗口」

- 官方只有账户级魔粒余额（`/openapi/v1/magicubes/balance`），没有 per-model
  额度端点（REFERENCES.md 已盘点）；「哪个模型刚才在限频」只能从本插件的
  429 事件流推断。
- **只有 `kind:"quota"` 算证据**：`rate_limit` 是瞬时限频（peer 退避重试，
  请求打得出去），`error` 是未知。把任何 429 都当耗尽是 0.2.0 已修掉的误判
  （QUOTA 快速失败 vs RATE_LIMIT 退避两条路）。事件流的 kind 读的是
  `llm-error-fix` **重分类后**的 code——与退避策略、面板事件流同一份口径，
  不另立一套。
- **窗口**（`exhaustionWindowMinutes`，默认 60，夹 [5,1440]）：额度按天重置，
  昨天的耗尽不该关掉今天的模型。
- **不推断恢复**：成功的流不发事件（`eventOfChunk` 成功 chunk 返回 null），
  「模型已恢复」在现有数据里**不可观测**。要恢复信号得给成功调用记账
  （`recordCall` 现在是按流计次、含失败，分不清成败），那是另一本账，
  与 usage-observer 头注的分工（不重复造全局账本答得了的账）冲突。
  **代价明示**：按天重置若在窗口内发生，模型最多灰显满一个窗口。方向保守
  （宁可少提供一会，不提供注定 429 的模型），且灰显带原因不是静默消失。

## 三、接线：单一生产者，三个消费者

- 生产者：`provider-reconcile.ts` 每遍收敛读 `usageStore.events()`（读失败
  降级空集 + warn，不炸链）→ `publisher.publish(entries, enabledIds, unavailable)`
  → `state.unavailableIds`。放在收敛环里而不是快照/路由里：**只在同一处算**，
  picker 与两个面板 roster 才不可能漂移；收敛节奏（pollSeconds）即生效节奏。
- 消费者：picker（`buildDescriptors` 丢弃）、`snapshot-aggregate.ts` 与
  `routes/provider.ts` 的 roster（都读 `state.unavailableIds`，不自己算）。

## 四、测试里踩到的一个真坑：读缓存会Mask 后写的文件

端到端用例（`test/provider-routes.test.mjs`）第一版写法：先 POST 触发过
一次收敛，再写 usage.json，再断言 roster 灰显——**红**。原因：`usage-store`
的进程内读缓存 TTL 是 1 秒，前一次收敛（事件文件不存在）的答案被缓存住，
随后几毫秒写文件对 `events()` 不可见。修法：事件文件在**第一次收敛之前**
落盘（模块级 seed），并在注释里写明「晚写几毫秒整条链就哑掉」。
这个坑值得记：它不是被测代码的缺陷，是**测试自己与缓存时序的耦合**——
凡是「写文件 → 触发读」的端到端用例，都要问一句「这个读有没有缓存」。
