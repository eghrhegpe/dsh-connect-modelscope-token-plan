# 0.6.3 过程档案——插件卡信息架构收敛（2026-10-19）

> 这不是入门路径。公开行为变化看 [CHANGELOG.md](../../CHANGELOG.md) 的 `[0.6.3]` 节。
> 本文只记病灶取证、判据与取舍。

## 一、起因：同族插件（商汤）的同类缺陷，逐条对照本仓

用户给出商汤插件（`dsh-connect-sensenova-token-plan`）的修复结论与两张截图（商汤
v0.8.0 已修 / 魔搭 v0.6.2 未修），问本仓是否有同一族问题。逐条取证结论：

| 商汤的病灶 | 本仓状态 | 证据 |
|---|---|---|
| 卡内 `h1` 复述外壳已打印的插件名 | **同样存在** | `src/client/panel-page.ts:358` 原为 `h("h1", { style: S.title }, tt("panel.title"))`；截图上「魔搭模型接入」出现两次 |
| 「更新于 / 刷新」独占一行、左半边空 | **同样存在** | `S.header`（`padding: "16px 0 12px"`）里只有 `h1` + `spacer` + 状态簇 |
| 卡内自带纵向内边距叠加外壳留白 | **同样存在** | `S.content` 原为 `padding: "6px 0 56px"`，`S.header` 另有 `16px 0 12px` |

## 二、那 32px 是谁的：不是插件的，不该抵消

结论（来自商汤会话，同一份外壳）与本地复核一致：插件卡由**两段**组成——外壳的
卡头（标题 + 版本徽章 + 包名 + 描述）与其下插件自己渲染的区域。两段之间那条规则在
宿主包里：

```
.detailSections { display:flex; flex-direction:column; gap:32px; margin-top:32px }
.detailSection  { display:flex; flex-direction:column; gap:12px }
```

**这段间距由外壳统一控制，所有插件一律，插件不该去抵消它**——抵消会破坏所有卡片的
统一节奏。所以病灶在插件这一侧：卡内又印了一遍同名标题，于是那 32px 呈现为「一个被
切成两半的表头」。

顺带记录一条反例以免误判成生态约定：魔搭与商汤同属一套脚手架，两边都有这个 `h1`；
Agnes 没有——**出现两次不代表它是约定，只代表脚手架抄了一遍**。

## 三、三处改动与判据

1. **名字只留一处**。删卡内 `h1`，删中/英字典的 `panel.title`（`src/client/i18n.ts`），
   删随之无用的 `S.title`。名字的唯一来源是 `locale/<lang>.json` 的 `meta.title`。
   记录那 32px 实证的注释写在 i18n 的 zh 字典头上（原先只有一句「外壳自己的查表」，
   没写它长什么样、也没写它对不对——改的人只看到「重复」，看不到「重复从哪来」）。
2. **一行装两样东西**。新的 `S.tabRow`（`display:flex; alignItems:stretch;
   gap:12; borderBottom; marginBottom:4`）左边放 `role="tablist"` 的三个 tab，右边放
   状态簇 + 刷新，`S.spacer` 居中撑开。分隔线从 tab 条挪到整行；`alignItems: stretch`
   让每个 tab 撑满行高，2px 激活下划线正好压在线上。`S.cluster` 加
   `alignSelf: center`，不压线。
   - **ARIA**：`role="tablist"` 里只留 tab。刷新按钮与「更新于」在 tablist **外层**——
     把非 tab 元素塞进 tablist 是无障碍上的错误，读屏会把它们当成 tab 念。
   - **取舍**：这一行现在随内容一起滚（原先名义上 pinned）。外壳整页是 `overflow:auto`，
     所谓固定本来就没真正生效，实际观感无损失；`S.scroll` 保留，因为它服务于「slot 给出
     确定高度」的场合（那时没有这条 flex 链，折线以下会被截掉）。
3. **卡内纵向内边距归零**。`S.content` 从 `6px 0 56px` 改为 `0`。6px 是为已删头部行留的，
   56px 是它还当整页用时留下的化石（那时上下留白得自己负责）；两者叠加外壳的 32px 段
   间距与 48px 页底，描述到 tab 之间空了 48px、页尾空了 104px。横向留白一直由外壳负责
   （卡内水平内边距本来就是 0），不动。

## 四、测试：把「重复合法化」的钉子反向

商汤那条旧钉子的形态值得记下来：断言「卡头名与卡内标题必须**相等**」。它本意是防
两个表面漂移，实际效果却是**让重复永久合法化**——只要两边一样，重复就是绿的。

本仓本次新增两道：

- `test/panel.test.mjs` §6e：名字由 locale 文件提供；`zh["panel.title"]` 与
  `en["panel.title"]` **必须为 undefined**（缺席断言）。
- `test/dom-render.test.mjs` §1a：在**渲染出来的真 DOM** 上钉四件事——`h1` 数为 0；
  页根文本不含 `locale/zh.json` 的 `meta.title`；页根文本不含裸键名 `panel.title`
  （只删键不删调用点时 `tt()` 会把键名渲染上屏，那是同一族坑的另一种长相）；tab 行
  自己带 `borderBottom` 且 `alignItems: stretch`，「更新于 / 刷新」的祖先链落在 tab 行上
  且刷新按钮在 tablist 之外。同一节还钉住卡内容器不自带纵向内边距。

`test/dom-render-react.test.mjs` §2 的第三个采样点原先是 `h1`（节点复用），随标题删除
换成 tab 行里的第一个 tab——采样点本身不承重，承重的是「重渲染后仍是同一批 DOM 对象」。

## 五、变异实证：两条新断言各抓什么，以及一条自己抓自己的教训

新增的排版断言跑测试**永远挖不到**（语法合法、类型也对），所以按纪律做变异实证：改
`src/` 里的真实代码 → `DSH_DOM_TARGET=src node test/dom-render.test.mjs` 读退出码与
点名 → 按原字节还原（不用 `git checkout`，会带走并行会话的未提交改动）。

| 变异 | 断言是否点红 |
|---|---|
| 卡内把插件名以 `h1` 复述 | ✅「卡内不得有 h1」 |
| 卡内以普通 `div` 复述插件名（无 h1） | ✅「卡内文本不得复述插件名」（`h1` 计数抓不到这一种） |
| 卡内容器加回 `padding: "6px 0 56px"` | ✅「卡内祖先节点不得有上内边距」 |
| tab 行 `alignItems` 从 stretch 翻成 center | ✅ tab 行那条 `strictEqual` |
| 刷新按钮搬进 `role="tablist"` | ✅「刷新按钮必须在 tablist 之外」 |

**自己抓自己**：内边距断言最初写的是 `tabRow.parentElement`。它没点红——因为 tab 行与
渲染体之间还夹着告警条之类的中间节点，**内边距挂在渲染体上，而断言检查的是另一个
元素**（正是本仓「门禁在核错对象」那一类绿灯撒谎）。改成沿祖先链逐层判定才咬得住。
另有一个小口径：内联 `padding: 0` 经 jsdom 序列化回来是 `padding-top: "0px"`（不是空
串），把「0px」判成有内边距会误伤正确写法——判据用「数值非零」的正则，而不是「非空」。
