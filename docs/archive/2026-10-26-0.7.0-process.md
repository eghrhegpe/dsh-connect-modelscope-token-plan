# 0.7.0 过程档案：出图工具从「下次启动生效」改成可撤销挂载

> 冻结档案：记录 0.7.0 这一轮的病灶、取证、判据与被否掉的方案。
> 与现行代码冲突时以 `src/host/draw-register.ts` 头注与 `AGENTS.md` 三条事实为准。

## 病灶：我们把宿主能力写小了

面板上「开关保存后要重启 DSH 才生效」这句提示，一直是照着本仓注释写的：

- `src/host/draw-register.ts` 的 `type ToolsService = { register?: (definition: unknown) => void }`
  —— 类型上就说「没有返回值」；
- 调用处 `tools.register(defineDrawTool({...}))` 的返回值直接丢掉；
- `src/host/draw-tool-state.ts` / `docs/PROVIDER-HOT-RELOAD.md` 复述同一句：
  「tools registry 没有 unregister」。

这三处互相引用，于是「没接线」被读成了「宿主不支持」。

## 取证：宿主一直返回 disposer

- 本机装的宿主 `runtime.json` 报 `desktopVersion: 0.2.1-rc.2`；同版本 `@deepseek-ai/dsh-tools`
  的 `lib/types/index.d.ts` 里 `register(definition: ToolDefinition): () => void`，
  实现走 `this.layers.effect(...)`（`lib/index.js`），disposer 执行的是 `entity.undo()`。
- 兄弟插件早就在用：`dsh-connect-workbuddy` 的 `image-tool.ts` 把
  `register(definition: unknown): () => void` 写成接口，`index.ts` 的 `syncImageTool` 开/关
  各一次注册与注销，并把 `dispose` 绑到自己的 `ctx.effect`；`dsh-connect-trae` 同型。
- 也就是说：**同一台 Host、同一条注册缝，生产可用**。缺的是我们的接线，不是宿主能力。

## 判据（落地形状）

1. **契约进类型**：`register?: (definition: unknown) => (() => void) | void`；
   拿到函数就存进闭包，关掉调它。
2. **控制面收在一处**：`createDrawToolMount()` 暴露 `sync()` / `dispose()` / `mounted()`。
   路由只改 desired state 并 `await syncDraw()`（与 `reconcile` 同一纪律），
   挂/卸的判定与串行化都在控制器里，不散进路由。
3. **卸载即销毁**：`apply()` 的 teardown 先 `dispose()`（摘工具）再清状态、销毁作业表；
   否则插件卸载/热重载后 registry 里留一个僵尸工具，同名重挂会被宿主拒。
4. **不谎报**：注册成功但宿主没给句柄 → 缺席原因 `not-removable`，面板直说「挂上了摘不掉」，
   而不是假装关掉了。旧 Host 仍能挂上、仍会报这个原因。

## 被否掉的方案

- **维持「下次启动生效」**：可行，但那是把缺的接线讲成宿主的限制；用户关掉开关后工具
  还在上下文里，会被 agent 继续调用。
- **让 `routes/draw.ts` 自己去 `ctx.get("tools")` 现挂现卸**：路由层会多出一条服务依赖，
  且挂载/注销逻辑分裂成两处；`apply()` 是唯一装配点，控制器属于那里。
- **把「同名已注册」的错误当作「已经挂上了」吞掉**：掩盖真正的重复注册 bug，且旧代码
  恰恰是因为吞掉返回值才从不报错——同类沉默不重复引入。

## 顺手修掉的一处「绿灯撒谎」

全量首跑时 `host-range` / `peer-imports` 同时红，报 `src/host/draw-register.ts` 少了
`@deepseek-ai/dsh-tools` 这条动态导入。AST 路看得见、token 路看不见。

根因在 `test/helpers/peer-imports.mjs` 的词法路：`ts.createScanner` 对带 `${` 的模板只返回
TemplateHead，后续片段必须 `reScanTemplateToken()` 续扫；裸循环 `scan()` 会让成对的反引号
互相错位，把夹在中间的 `import("...")` 吞进一个假「模板 token」。旧文件反引号奇偶碰巧配对，
所以一直是绿的——本次改动改了模板分布，才把它照出来。

修法是维护模板栈并在 `}` 处重扫；另加一条夹具回归（模板字面量夹在动态导入前后）。
变异对照：把修复前的循环贴回去，同一夹具下 token 路数出 0 个导入点、`draw-register.ts`
也是 0 vs 1，确认夹具真能钉住它。

## 验证

- `npm run build` → `node test/run-all.mjs`（45/45）→ `npm run typecheck`（0 错）。
- 出图域新增 3 节：热挂/热卸、`dispose()` 幂等且之后不复活、旧 Host 无句柄时
  `not-removable` 且只 warn 一条。
- **未做**：真机重启后的端到端冒烟（面板翻开关 → 会话里工具立刻可用/消失）。属发布后验证项。
